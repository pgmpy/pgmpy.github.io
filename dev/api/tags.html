Tags#

pgmpy objects describe themselves with skbase tags, for example the data types a causal discovery algorithm can handle, or the assumptions its guarantees rely on. Tags can be read with get_tag / get_class_tag and used to find objects with skbase.lookup.all_objects():

from skbase.lookup import all_objects

from pgmpy.causal_discovery._base import BaseCausalDiscovery

all_objects(
    object_types=BaseCausalDiscovery,
    package_name="pgmpy.causal_discovery",
    filter_tags={"data_types": "continuous", "assumption:linearity": False},
)

All tags are registered in pgmpy.registry.

all_tags([object_types, as_dataframe])

List the tags that apply to the given object types.

check_tag_is_valid(tag_name, tag_value)

Check that a tag value has the type registered for the tag.

Causal Discovery Algorithms#

object_type

Type: one of 'causal_discovery', 'ci_test', 'structure_score', 'bivariate_score', 'supervised_metric', 'unsupervised_metric'

Type of the object, e.g. "causal_discovery" or "ci_test".

Set by the base class of each object type. Use it with pgmpy.registry.all_tags() to list the tags that apply to an object.

name

Type: str

Unique lowercase name of the object.

CI tests, structure scores, bivariate scores, and metrics can be selected by this name, e.g. PC(ci_test="pearsonr"), GES(scoring_method="bic-g"), or PC(return_type="dag").fit(data).score(X=data, metric="correlation_score").

data_types

Type: list with elements from 'discrete', 'continuous', 'mixed'

Data types the object can be applied to.

For causal discovery algorithms that use a CI test, a structure score, a bivariate score, or a pairwise estimator, the class-level value is every data type supported by some available component. fit narrows it to the data types that every component used for fitting also supports.

The value is a list rather than a tuple because skbase.lookup.all_objects only matches single elements of a tag value in filter_tags when the value is a list.

identifiable_graph

Type: one of 'dag', 'cpdag', 'pag'

How far the causal discovery algorithm can identify the causal graph.

  • "dag": Every edge is oriented, e.g. by relying on functional or noise assumptions (ANM), on patterns in the data (VarSort), or on an expert (ExpertInLoop).

  • "cpdag": The graph is identified only up to its Markov equivalence class, e.g. PC and GES. With expert knowledge, more edges can be oriented (a maximally oriented PDAG).

  • "pag": The graph is identified only up to a partial ancestral graph, for methods that allow latent variables.

This describes the method, not the type of causal_graph_: an algorithm with a return_type parameter can convert its result, e.g. PC(return_type="dag") returns one arbitrary DAG from the equivalence class.

requires_target

Type: bool

Whether the causal discovery algorithm requires a target variable to be specified, e.g. TAN.

capability:multivariate

Type: bool

Whether the causal discovery algorithm can learn a graph over more than two variables.

False for bivariate methods, such as ANM and IGCI, that orient the edge between exactly two variables.

capability:expert_knowledge

Type: list with elements from 'forbidden_edges', 'required_edges', 'search_space', 'temporal_order'

Constraints from pgmpy.causal_discovery.ExpertKnowledge that the causal discovery algorithm respects.

assumption:causal_sufficiency

Type: bool

Whether the method assumes there are no unobserved common causes of two or more observed variables.

assumption:acyclicity

Type: bool

Whether the method assumes the true causal graph has no directed cycles.

assumption:faithfulness

Type: bool

Whether the method assumes every conditional independence in the data is implied by the true causal graph.

Methods that need a weaker assumption, such as the sparsest Markov representation assumption of SP, set this to False and describe the weaker assumption in their docstring.

assumption:linearity

Type: bool

Whether the method assumes each variable is a linear function of its parents.

assumption:additive_noise

Type: bool

Whether the method assumes each variable is a function of its parents plus independent, additive noise.

assumption:gaussian_noise

Type: bool

Whether the method assumes the noise terms are Gaussian.

assumption:non_gaussian_noise

Type: bool

Whether the method assumes the noise terms are non-Gaussian, e.g. LiNGAM.

assumption:low_noise

Type: bool

Whether the method assumes the effect is a (nearly) deterministic function of its cause, e.g. IGCI.

Bivariate Scores#

object_type

Type: one of 'causal_discovery', 'ci_test', 'structure_score', 'bivariate_score', 'supervised_metric', 'unsupervised_metric'

data_types

Type: list with elements from 'discrete', 'continuous', 'mixed'

Data types the object can be applied to.

Type: bool

Whether the method assumes each variable is a linear function of its parents.

assumption:additive_noise

Type: bool

Whether the method assumes each variable is a function of its parents plus independent, additive noise.

assumption:gaussian_noise

Type: bool

Whether the method assumes the noise terms are Gaussian.

input_type

Type: one of 'cause_residual', 'cause_effect'

What the two inputs of the bivariate score are.

  • "cause_residual": A candidate cause and the residuals of regressing the effect on it, as passed by ANM. The score measures how dependent the residuals are on the cause.

  • "cause_effect": A candidate cause and effect, as passed by IGCI. The score must be asymmetric, since the algorithm compares score(x, y) with score(y, x).

Algorithms only accept built-in scores of the input type they pass.

Supervised Metrics#

object_type

Type: one of 'causal_discovery', 'ci_test', 'structure_score', 'bivariate_score', 'supervised_metric', 'unsupervised_metric'

Type of the object, e.g. "causal_discovery" or "ci_test".

Set by the base class of each object type. Use it with pgmpy.registry.all_tags() to list the tags that apply to an object.

name

Type: str

Unique lowercase name of the object.

CI tests, structure scores, bivariate scores, and metrics can be selected by this name, e.g. PC(ci_test="pearsonr"), GES(scoring_method="bic-g"), or PC(return_type="dag").fit(data).score(X=data, metric="correlation_score").

default_for

Type: one of 'discrete', 'continuous', 'mixed', 'supervised', 'unsupervised', None

What the object is used by default for, or None.

  • CI tests and structure scores: the data type for which the object is selected when a causal discovery algorithm is given ci_test=None or scoring_method=None.

  • Metrics: "supervised" or "unsupervised", for the metric used by pgmpy.causal_discovery._base.BaseCausalDiscovery.score() when metric=None.

requires_data

Type: bool

Whether the object needs data.

False for oracle CI tests such as IndependenceMatch and for metrics that only compare two graphs.

is_symmetric

Type: bool

Whether swapping the two inputs leaves the result unchanged.

For CI tests, swapping X and Y. For supervised metrics, swapping the true and the estimated graph.

requires_true_graph

Type: bool

Whether the metric compares an estimated graph against a true graph (supervised) rather than against data.

supported_graph_types

Type: list with elements from DAG, PDAG, MAG, ADMG

Graph classes from pgmpy.base that the metric accepts.

output_type

Type: one of 'scalar', 'tuple', 'dict', 'dataframe'

Type of the value returned by evaluate.

  • "scalar": A single number.

  • "tuple": A tuple of numbers, e.g. FisherC(compute_rmsea=True) returns the p-value and the RMSEA.

  • "dict": A dict of named results, e.g. precision and recall from AdjacencyConfusionMatrix.

  • "dataframe": A pandas.DataFrame, e.g. one row per implied CI from ImpliedCIs.

If the output depends on a hyperparameter, the class-level value is the default output and __init__ sets it for the instance.

lower_is_better

Type: bool

Whether a lower value of the metric means a better graph.

Only meaningful when output_type is "scalar"; False otherwise.
